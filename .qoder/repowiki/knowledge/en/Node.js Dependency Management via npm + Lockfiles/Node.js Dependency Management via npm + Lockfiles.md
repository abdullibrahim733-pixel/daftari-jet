## Approach

The Daftari Dashboard is a Node.js / Next.js project that manages dependencies exclusively through **npm** (no pnpm, yarn, or bun). Two lockfiles pin every transitive dependency:
- `package-lock.json` — the canonical npm lockfile for runtime and dev dependencies.
- `skills-lock.json` — a custom lockfile for agent-facing skill definitions sourced from GitHub (`neondatabase/agent-skills`).

There is no vendoring of third-party code; all packages are installed into `node_modules/` at install time.

## Key Files

- `package.json` — declares runtime deps (`next`, `react`, `@aws-sdk/client-s3`, `@neondatabase/serverless`, `@vercel/blob`, `zod`) and dev deps (`eslint`, `typescript`, `tailwindcss`, `postcss`, `@types/*`). All versions are pinned to exact values under `dependencies`; only `devDependencies` use caret ranges. The `engines` field constrains Node to `>=24.0.0`.
- `package-lock.json` — generated by npm; used as the source of truth for reproducible installs.
- `skills-lock.json` — pins two skills (`neon`, `neon-postgres`) with `source`, `sourceType: "github"`, `skillPath`, and a `computedHash` per skill.
- `.github/workflows/ci.yml` — CI uses `npm ci` (not `npm install`) and caches the npm registry cache directory (`cache: npm`). It also runs `npm audit --audit-level=high` after building.
- `scripts/register-alias.mjs` — a small ESM bootstrap script imported by every test and CLI entry point via `--import ./scripts/register-alias.mjs` so TypeScript path aliases resolve at runtime without a bundler.

## Conventions Observed

1. **Exact version pinning in production dependencies.** Every runtime dependency in `package.json` uses an exact version string (e.g. `next: "16.3.8"`, `react: "19.3.0"`, `zod: "4.6.5"`), while dev dependencies use caret ranges (e.g. `"^3.1149.0"`). This keeps production builds deterministic while allowing dev tooling to drift within minor/patch bounds.
2. **CI enforces lockfile-only installs.** The workflow runs `npm ci`, which fails if `package-lock.json` is out of sync with `package.json`, preventing accidental drift between local and CI environments.
3. **No private registry configuration.** There is no `.npmrc`, `NPM_CONFIG_REGISTRY`, or `GOPRIVATE` equivalent; all packages come from the public npm registry and the public GitHub API (for skills).
4. **Skills are separately locked.** Agent skills are not managed by npm; they are declared under `.agents/skills/` and locked via `skills-lock.json`, which records the GitHub repo, branch/path, and a SHA-like `computedHash` for each skill. This mirrors how package managers pin transitive dependencies.
5. **Runtime alias resolution is explicit.** Because this is a plain Node.js setup (no Next.js build-time TS transformation for tests/scripts), every Node invocation passes `--disable-warning=MODULE_TYPELESS_PACKAGE_JSON --import ./scripts/register-alias.mjs` so `src/` path aliases work at runtime. This is repeated across `test`, `test:watch`, `db:migrate`, `db:seed`, `db:reset`, and `jobs:run` scripts.
6. **Audit gate in CI.** After building, CI runs `npm audit --audit-level=high`, causing the job to fail on any high-or-above severity vulnerability.
7. **Node engine constraint.** `package.json` specifies `"engines": { "node": ">=24.0.0" }`, which is enforced by npm when the `engine-strict` setting is enabled (default in newer npm) or by the hosting platform (Vercel, which matches the `next` 16.x requirement).

## Constraints Enforced

- `npm ci` in CI (`.github/workflows/ci.yml`) requires `package-lock.json` to be present and in sync — it will abort otherwise.
- `npm audit --audit-level=high` in CI treats any high-severity vulnerability as a failure.
- `skills-lock.json` pins skills by `computedHash`, so updating a skill requires explicitly changing the hash in the lockfile (the `.agents/skills/` files alone are not enough to change what agents load).
- Runtime scripts must include the `--import ./scripts/register-alias.mjs` flag to resolve `src/*` imports; bare `node scripts/*.ts` invocations would fail because the alias resolver is not loaded.
