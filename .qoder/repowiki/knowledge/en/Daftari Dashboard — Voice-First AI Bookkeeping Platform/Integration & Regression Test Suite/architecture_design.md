Tests are flat per feature area (`auth.test.ts`, `capture.test.ts`, `corrections.test.ts`, `exports.test.ts`, `idempotency.test.ts`, `inventory.test.ts`, `media-acquisition.test.ts`, `pipeline.test.ts`, `providers.test.ts`, `reports.test.ts`, `session.test.ts`, `xlsx.test.ts`) and share a single test helper under `helpers/fixture.ts`. The fixture bootstraps an isolated SQLite file (via `getDatabase` + `runMigrations`), seeds a user/business/membership triple, builds a `BusinessContext` through `contextForTesting`, and also provisions a second tenant so multi-tenant isolation can be asserted. It redirects `DAFTARI_DATA_DIR` to a per-process temp directory so media acquisition writes never touch production storage, and cleans up all temp dirs in a Node `after` hook. Tests import production modules directly via `@/server/*` path aliases rather than HTTP endpoints, exercising repositories, domain logic, and middleware together against a live DB.
